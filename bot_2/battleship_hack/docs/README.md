# Документация bot2

Состояние на 10 октября 2026 года. Эта папка описывает реализацию в `bot_2/battleship_hack`, а не соседние командные боты.

- [CHANGELOG.md](CHANGELOG.md) — этапы развития, результаты, исправленные ошибки и подходы, которые не следует повторять без новой гипотезы.
- [Журнал экспериментов](../experiments/bot2.md) — подробные серии, seed, run_id и matchId.
- [Инструкция запуска](../README.md) — эксплуатационные подробности.

## Назначение и текущее состояние

Бот автоматически играет в морской бой на платформе хакатона, записывает решения и результаты для сравнения стратегий. Реализован клиент TRAINING для встроенных EASY, MEDIUM и HARD. Бонусы из `MATCH_STARTED` применяются консервативной политикой (`USE_BONUS`); ставки не используются. Отключение: `use_bonuses = false` или `--no-use-bonuses`. Поддерживается только `bot2`.

Текущий выбор в [конфигурации](../configs/bot2.toml): `fleet-mc`, MEDIUM, один бой, общий лимит 360 секунд и до трёх попыток переподключения. `baseline` сохранён для контрольных запусков и отката выбора стратегии. Версия пакета — `0.1.0`; отдельные этапы алгоритма пока не имеют релизных тегов.

По журналу экспериментов: baseline — 2/2 победы EASY и 0/1 MEDIUM; fleet-mc — 10/10 MEDIUM и 2/8 HARD. Эти выборки не доказывают превосходства над baseline: условия и число матчей различались. Экспериментальная hard-edge: 11/21 побед HARD, включая серию 10/20; среднее до победы в последней серии — 48 выстрелов. Резерв — поиск катеров; устойчивый рост винрейта ещё не подтверждён. [Разбор серии](../experiments/hard-edge-20.md).

## Устройство

Python 3.12.9, окружение через `uv`. Зависимости: `websockets`, `httpx`, `python-dotenv`, `duckdb`.

| Компонент | Ответственность |
|---|---|
| [cli.py](../src/battleship_hack/cli.py) | Команды, TOML, загрузка `.env`, seed, локальная блокировка второго процесса, завершение и импорт |
| [client.py](../src/battleship_hack/client.py) | WebSocket, события партии, отправка действий, переподключение, HTTP-статистика |
| [game.py](../src/battleship_hack/game.py) | Допустимая расстановка, состояние стрельбы, реестр стратегий |
| [telemetry.py](../src/battleship_hack/telemetry.py) | JSONL, удаление секретов, снимки кода, импорт DuckDB и отчёт |
| [smoke.py](../src/battleship_hack/smoke.py) | Локальная проверка протокола и аналитики без внешнего сервера |

Поток работы: CLI загружает настройки → создаёт журнал и снимок версии → клиент подключается и запрашивает TRAINING → принимает правила партии → размещает флот и отвечает на `TURN_REQUESTED` → сохраняет исход → после заданного числа матчей отключается и импортирует журнал в DuckDB.

Правила поля, флота, касания и дедлайна берутся из событий конкретной партии. При reconnect внутри процесса принятые выстрелы восстанавливаются из снимка; незавершённая команда не повторяется вслепую. Неизвестная существующая партия вызывает остановку. Поддержка модификаторов базовая; результатов реальных серий для каждого модификатора в журнале нет.

## Стратегии

| Имя | Поиск и добивание | Статус |
|---|---|---|
| `baseline` | Случайный поиск доступной клетки, добивание соседей | Контрольная стратегия |
| `density` | Карта допустимых положений оставшихся кораблей с учётом известных клеток | Доступна; локальная выборка не показала выигрыша, отдельной боевой серии нет |
| `fleet-mc` | В поиске — карта занятости по совместимым целым флотам; при добивании — density | Текущий default TRAINING, успех на MEDIUM |
| `fleet-mc-duel` | DUEL: взвешенный two-shot lookahead по выборке флотов | Контрольный откат для рейтинга |
| `fleet-mc-duel-v2` | Как duel, ничьи — чётная диагональ checkerboard | RANKING auto на DUEL и THREE_MUSKETEERS |
| `fleet-mc-interior` | Как duel-v2, hunt и расстановка смещены внутрь поля | Эксперимент против edge-avoiding команд |
| `hard-edge` | MC и добивание с моделью HARD: многопалубные на периметре, катера внутри; fallback на fleet-mc | Отдельный эксперимент TRAINING/HARD; результаты в журнале |
| `hard-quadrants` | Крупные корабли как hard-edge; катера — точная карта по одному в каждой неизвестной четверти | Эксперимент HARD с возвратом к hard-edge при противоречиях |

Расстановка у всех стратегий общая: случайный допустимый флот. Изменения расстановки отдельно в бою не сравнивались.

MC ограничен 80 мс или 12% дедлайна хода, 1000 принятыми флотами и 4000 попытками. При менее чем 30 сэмплах или отсутствии карты применяется density; при активных попаданиях и другом правиле касания также используется density. Последовательная выборка смещена: это приближение, а не точное байесовское распределение. Seed сохраняется, но временной бюджет делает точное повторение зависимым от скорости машины.

## Запуск и анализ

Все команды выполняются из `bot_2/battleship_hack/`:

```bash
uv sync --python 3.12.9
uv run battleship-hack smoke
uv run battleship-hack run --strategy fleet-mc --opponent MEDIUM --matches 1 --experiment fleet-mc-medium
uv run battleship-hack run --strategy baseline --opponent MEDIUM --matches 1 --experiment baseline-medium
uv run battleship-hack ingest
uv run battleship-hack report
```

Создать `.env` по [примеру](../.env.example) в папке проекта или `bot_2/`: `BOT_TOKEN` обязателен, `BOT_PLATFORM_ID` — необязательный UUID для HTTP-аналитики. Секреты не помещать в документацию.

TRAINING тоже меняет Elo. Подключение первоначально находится в RANKING: запрос TRAINING не отменяет уже назначенный матч. При сопернике команды клиент прекращает игровые действия, но это не отменяет серверную партию и возможное техническое поражение. Локальный lock защищает только от второго процесса из той же рабочей папки.

## Данные и воспроизводимость

- `data/bot2/logs/<run_id>.jsonl` — первичный журнал событий и решений.
- `data/bot2/versions/<run_id>/` — снимок исходников и конфигурации, хеш, Git commit и признак незакоммиченных изменений.
- `data/bot2/analytics.duckdb` — восстанавливаемая БД: `events`, представления `runs`, `battles`, `experiments`. Повторный импорт не дублирует `event_id`.

Локальный `battle_id` отличается от платформенного `matchId`. HTTP-сопоставление эвристическое; при отсутствии UUID или неоднозначности рейтинг остаётся `NULL`. Ошибка HTTP не останавливает игру. Время решения измеряется от начала обработки до отправки команды и не равно полной сетевой задержке. Анализировать БД следует после импорта либо на копии.

## Как поддерживать документацию

После изменения поведения обновлять это описание и добавлять этап в CHANGELOG. Для каждого эксперимента сохранять гипотезу, конфигурацию, seed, версию/снимок, размер выборки, результат и решение в журнале экспериментов. Отрицательные результаты не удалять. Перед новой стратегией читать раздел ограничений в CHANGELOG и указывать, какое новое условие оправдывает повторную проверку.

Спецификация платформы: [правила](../../../docs/platform/guide.md), [сообщения](../../../docs/platform/messages.md), [значения и ошибки](../../../docs/platform/values.md), [HTTP API](../../../docs/platform/http-api.md). [Исследование стратегий](../../../docs/research/research.md) содержит идеи, а не доказательства их эффективности в этом боте.


Первый контроль hard-quadrants: 3/3 побед HARD (41/50/36 выстрелов) против 2/3 у hard-edge в чередующейся серии; ошибки и fallback отсутствуют. Для оценки устойчивого улучшения нужна более длинная серия. [Подробности оптимизации](../experiments/hard-quadrants-v1.md).
