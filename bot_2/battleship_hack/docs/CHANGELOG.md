# История развития bot2

Восстановлено 10 октября 2026 года по коду и [журналу экспериментов](../experiments/bot2.md). Этапы ниже идут от ранних к поздним; это этапы разработки, а не номера релизов. На момент подготовки весь `bot_2/battleship_hack/` не отслеживается Git: отдельные коммиты реализации и точные времена обновлений недоступны. Версию конкретного запуска следует искать в `data/bot2/versions/<run_id>/`. Результаты ниже перенесены из журнала экспериментов; первичные JSONL и БД при подготовке документации повторно не анализировались.

## 1. Первый клиент и наблюдаемость — first-training

Добавлены asyncio/WebSocket, случайная допустимая расстановка, baseline, ограниченный TRAINING-запуск, JSONL, снимки версии и импорт DuckDB. Цель — пройти полный цикл партии и сохранить материал для следующих итераций.

Результат: WIN против EASY, 62 выстрела, без боевых ошибок; рейтинг отсутствует, поскольку UUID бота не задан. Локальные smoke-проверки подтвердили обмен, reconnect, импорт без дублей, неполную строку JSONL и удаление секретов.

Решение: инфраструктура пригодна для экспериментов; одна победа не оценивает силу стратегии. Запуск: `dd592c9b-407b-4258-be98-e33c4704bea4`.

## 2. HTTP-аналитика рейтинга — second-training

Добавлен UUID бота для получения статистики и сопоставления с платформенным журналом. Повторный baseline/EASY: WIN, 59 выстрелов, Δ Elo +0,465052.

Обнаружено: запрос общей HTTP-статистики без обязательного `kind` возвращал 400. Исправлено на `kind=TRAINING`, ответ проверен — 200. Боевой обмен при этом работал.

Решение: брать рейтинг из серверных данных, неизвестные значения оставлять `NULL`. Запуск: `a2ee3743-133a-404e-ba13-9e6f1661158c`.

## 3. Первая проверка MEDIUM и исправление отчёта — first-medium-training

Без изменения baseline повышена сложность: LOSS, 63 выстрела, Δ Elo −8,495102; боевых ошибок нет.

После боя отчёт упал при конвертации DuckDB TIMESTAMPTZ в Python из-за требования `pytz`. Исправлено SQL-преобразованием времени в строку, проверка рейтингового снимка добавлена в smoke. Данные сохранены, отчёт после исправления прочитан.

Решение: отделять поражение стратегии от технического сбоя. Запуск: `bf482d40-b682-4566-96c4-39ebc297a5f8`.

## 4. Карта положений и выборка флотов — fleet-mc-medium-v1

Гипотеза: совместимые целые флоты сократят промахи поиска. В проигрыше baseline/MEDIUM было 46 промахов поиска и один промах добивания.

Добавлены `density` и `fleet-mc`, обновление состава после SUNK, исключение известных пустых клеток и добивание по допустимым линиям. Расстановка прежняя; baseline сохранён. MC получил временной бюджет и fallback в density.

На восьми одинаковых локальных досках среднее число выстрелов: baseline 55,875; density 58,125; fleet-mc 54,875. Density в этой выборке оказался хуже baseline, а преимущество MC мало; этого недостаточно для общего вывода.

Боевая серия fleet-mc/MEDIUM: 5/5 побед, среднее 59,4 выстрела, Δ Elo +6,158023, p95 обработки/отправки 50,458 мс, ошибок нет.

Решение: fleet-mc выбран default; baseline доступен через `--strategy baseline`. Превосходство над baseline не доказано сопоставимой серией. Запуск: `1f3768ec-b85e-4d3a-9068-1a6db2e21d6d`.

## 5. Повтор MEDIUM — fleet-mc-medium-v1-repeat

Алгоритм и расстановка не менялись. Ещё 5/5 побед, среднее 54,0 выстрела, Δ Elo +5,347388, p95 48,622 мс, ошибок нет.

Итого MEDIUM: 10/10 побед, среднее 56,7 выстрела. Решение: оставить текущий выбор, не считать наблюдаемый винрейт гарантией. Запуск: `dc1bc10d-ce61-4d81-9c73-97539b958545`.

## 6. Перенос на HARD — fleet-mc-hard-v1

Тот же алгоритм: 2 победы и одно поражение, Δ Elo +7,252608, технических ошибок нет. В поражении — 29 промахов поиска и шесть промахов добивания.

Решение: собрать больше данных до оптимизации; default оставить MEDIUM. Три матча не подтверждают устойчивую силу на HARD. Запуск: `4da52904-e860-416a-a1d9-26add722f598`.

## 7. Отрицательная повторная серия HARD — fleet-mc-hard-v1-repeat

Без изменения стратегии: 0 побед и пять поражений, Δ Elo −25,485860, p95 49,412 мс, технических ошибок нет. Промахи поиска по матчам: 25, 38, 13, 30, 26; добивания: 4, 2, 1, 8, 2.

Итого HARD: 2/8 побед (25%). Решение: текущая версия не подтверждает устойчивого преимущества против HARD; оптимизация отложена, результаты сохранены. Причина слабого результата не установлена: поиск, добивание и расстановка требуют раздельных проверок. Запуск: `90e2d0ab-52d0-48f7-a4ec-d260e1cfb71b`.

## Что не повторять без новой гипотезы

| Подход или ошибка | Что известно | Условие следующей проверки |
|---|---|---|
| Объявлять baseline достаточным для MEDIUM | Единственный бой проигран; выборка слишком мала | Контрольная серия, сопоставимая с fleet-mc |
| Выбирать density только по привлекательности карты | На восьми локальных досках 58,125 против 55,875 выстрела baseline; боевой серии нет | Новая гипотеза или расширенная сопоставимая выборка |
| Считать успех MEDIUM переносимым на HARD | 10/10 MEDIUM, но 2/8 HARD тем же кодом | Отдельная серия HARD с контролем первого стрелка и компонентов стратегии |
| Повторять неизменённый fleet-mc/HARD как подтверждённое улучшение | Повтор дал 0/5, технических сбоев нет | Явная цель сбора данных либо конкретное изменение одного компонента |
| Называть MC точной вероятностью | Последовательная выборка смещена и ограничена временем | Проверенный иной метод выборки и измерение его стоимости |
| Сравнивать число выстрелов в поражении с выстрелами до победы | При поражении чужой флот может остаться жив | Сравнивать одинаковые исходы либо учитывать неполное завершение |
| HTTP-статистика без `kind` | Получены 400 | Сохранять обязательный `kind=TRAINING` |
| Возвращать Python-конвертацию TIMESTAMPTZ без учёта зависимостей | Отчёт падал после успешного боя | Сохранить SQL-преобразование либо проверить новую конвертацию smoke-тестом |
| Считать TRAINING безопасным для рейтинга | TRAINING меняет Elo; при подключении есть гонка с RANKING | Учитывать стоимость серии и стартовую гонку |

Это ограничения доказательств, а не пожизненный запрет на стратегии. Новые условия могут оправдать повтор, но должны быть записаны до серии.

## Следующее обновление

Дальнейший эксперимент пока не проведён: чередовать baseline/fleet-mc на одинаковой сложности, отдельно учитывать первый ход, промахи поиска и добивания; расстановку менять отдельным экспериментом.

Для нового этапа добавить: дату и идентификатор; проблему/гипотезу; изменение относительно контрольной версии; commit или снимок и run_id; параметры и seed; количество матчей, исходы, Elo, задержки и ошибки; вывод «оставить / откатить / недостаточно данных»; условия, при которых стоит вернуться к отвергнутому подходу. Полные таблицы матчей хранить в журнале экспериментов, здесь — основные решения и причины.


## hard-edge-v1 — модель расстановки HARD

По разбору восьми HARD: все 43 раскрытых многопалубных корабля лежали на периметре, все 20 раскрытых катеров внутри. Добавлена отдельная стратегия `hard-edge`, применяющая эту модель при поиске целых флотов и добивании. Последний катер ищется среди допустимых внутренних клеток без MC. Несогласованные наблюдения, недоступные положения и недостаточная выборка возвращают fleet-mc; модификаторы отключают профиль с начала матча. Причины сохраняются в DECISION. CLI разрешает профиль только с HARD. Общая расстановка и default fleet-mc/MEDIUM сохранены. Проверки и боевые результаты: [журнал](../experiments/bot2.md).

Первый проверочный HARD: WIN, 47 выстрелов (20 попаданий / 27 промахов), без fallback и технических ошибок, Elo по журналу +4.984; run_id `d04c0898-bab4-486d-8256-60f098bb6190`. Один матч не подтверждает превосходство; следующим нужна сравнимая серия.


## hard-quadrants-v1 — поиск катеров по четвертям

В 13 раскрытых полях HARD — по одному катеру на четверть, 88 найденных катеров в 29 партиях не противоречат шаблону. Добавлен профиль hard-quadrants: ранняя атака hard-edge сохранена, катера ищутся по точной карте совместимых четвертей с запретом касания и бюджетом времени. Противоречия возвращают hard-edge, его fallback на fleet-mc сохранён. Локальные результаты и чередующаяся боевая проверка — в [журнале](../experiments/bot2.md). Default сохранён.

Проверка hard-quadrants: 3/3 побед HARD, 42,333 выстрела в среднем до победы, Elo по журналу +10,677. Контроль hard-edge: 2/3, Elo +0,388. Ошибок и fallback нет. Шесть матчей — предварительный результат; следующие 20 боёв ещё не проведены.


## Бонусы — USE_BONUS

Добавлен `bonuses.BonusBag`: учёт использований из `MATCH_STARTED`/`MATCH_SNAPSHOT`, `USE_BONUS` на `TURN_REQUESTED`, обработка `BONUS_RESOLVED`/`BONUS_REJECTED`/`OPPONENT_BONUS_USED`. Политика: SALVO при добивании/охоте, SHIELD под угрозой, MINE у ореола своей расстановки, SONAR/DISTANCE в поиске с записью пустых клеток и forced-shot при distance 0. Оплата Elo учитывается sparingly (не тратим весь запас подряд). Конфиг `use_bonuses` / `--use-bonuses` / `--no-use-bonuses`. Ставки по-прежнему пропускаются.


## fleet-mc-duel-v2 — parity tie-break для DUEL

После серии рейтинговых DUEL с высоким процентом поражений офлайн сравнены политики на последних 15 RANKING-досках (частичные поля достраивались согласованно с промахами). Эксперимент «только one-shot без lookahead» оказался хуже `fleet-mc-duel` (~58.3 vs ~54.7 выстрелов). Итоговая `fleet-mc-duel-v2` сохраняет two-shot lookahead и меняет только выбор среди ничьих в пользу чётной диагонали checkerboard.

Симуляция 15×108 пар: mean shots **54.98** (v2) / **55.53** (duel) / **56.01** (fleet-mc); Δ v2−duel **−0.55**. Порог «≥0.5 лучше обоих» пройден. RANKING auto-switch на DUEL переведён на `fleet-mc-duel-v2`; откат — `--strategy fleet-mc-duel`. Артефакт: `data/bot2/duel-v2-sim-last15.json`. Живой винрейт ещё не измерен.

## THREE_MUSKETEERS — miss-race auto-switch и ранний SHIELD

На платформе включён `THREE_MUSKETEERS`: 3 выстрела за ход, промах тратит выстрел хода, попадание — нет. Раньше `fleet-mc-duel-v2` срабатывал только на DUEL, поэтому в «мушкетёрах» бот оставался на обычном `fleet-mc`/`fleet-mc-bigship` без two-shot sampler.

Изменения: `is_miss_race()` объединяет DUEL и THREE_MUSKETEERS; RANKING auto (`ranking-auto` / `fleet-mc`) переключает оба режима на `fleet-mc-duel-v2`. Политика бонусов ставит SHIELD сразу в «мушкетёрах» (DEFENDED обрывает чужой залп). Большие офлайн-симуляции по запросу не гоняем — проверка в рейтинге.

## fleet-mc-interior — hunt/placement внутрь поля

По журналу RANKING против «Низкие ожидания» (≈8/37, WR 22%): наши первые 8 выстрелов ~82% на краю, их корабли ~17% на краю; их точность ~43% против наших ~37%. Добивание сравнимо — проигрыш в поиске.

Новая стратегия `fleet-mc-interior` наследует `fleet-mc-duel-v2`: two-shot lookahead сохранён; hunt-оценки умножаются на `1 + 0.55·depth`, среди near-best (tolerance 12%) предпочитаются некраевые клетки, затем глубина и чётная parity. Расстановка через `place(..., prefer_interior=True)` и `Baseline.place_fleet()`.

Офлайн на 9 полных досках «Низкие ожидания» × 3 seed: mean shots **54.74** vs duel-v2 **57.11** (Δ −2.37; 18/7/2), доля края в первых 8 **70.8%** vs **90.7%**, среднее до первого попадания **6.8** vs **8.4**. Default ranking не переключён. Откат: `--strategy fleet-mc-duel-v2`.

## fleet-mc-schrodinger — вывод потоплений без SUNK

Подготовка к `SCHRODINGER_SHIP` (вместо SUNK приходит HIT). У interior попадания никогда не закрывались: не уменьшался оставшийся флот, не ставились ореолы, hunt по MC отключался до конца партии.

`fleet-mc-schrodinger` наследует interior и сам выводит потопление: кластер закрыт, когда никакое согласованное положение оставшейся длины не содержит его строго. Открытые кластеры разбирает выборка флотов, допускающая уже целый корабль. Без модификатора — тот же interior. Офлайн на 40 досках: **55.65** против **64.92** выстрела у interior (35/1/4). Живых боёв нет. Детали — в [журнале](../experiments/bot2.md).

Клиент при `SCHRODINGER_SHIP` переключает любую стратегию семейства fleet-mc (включая `ranking-auto`, `ranking-lowexp`, fleet-mc после reconnect новым процессом и гонку TRAINING/RANKING) на `fleet-mc-schrodinger`; `baseline`/`density` остаются явными контролями.

## fleet-mc-hunger — HUNGER_GAMES

Подготовка к «Голодным играм» (лимит выстрелов, например 20; исход — по числу попаданий). Наследует `fleet-mc-schrodinger-rim-v2`. Расстановка по сопернику: многопалубные на краю, против команд, стреляющих по краю (`RIM_HUNTERS`: Банька Парилка, История про Минск), — внутрь поля. По логам за первые 20 выстрелов соперника краевая расстановка дала большинству команд 0,75–4 попадания против 7–10 по внутренней, Баньке — 10,5 против 3,3. Поиск взвешивает длинные корабли по оставшимся выстрелам (офлайн +0,02…+0,18 ± 0,21 попадания, нейтрально). Бонусы: только SHIELD при добивании нашего корабля, остальные тратят выстрел. Клиент переключается автоматически по `modifier`. Подробности — в [журнале](../experiments/bot2.md).

## fleet-mc-hunger-heat — расстановка по карте выстрелов соперника

Отдельная вариация `fleet-mc-hunger`: стрельба прежняя, расстановка выбирается из пула флотов как наименее обстреливаемая по карте поисковых выстрелов этой команды (логи + онлайн-обновление), 15% матчей — случайная. SHIELD только при точности соперника >45%. Офлайн: 1,92 против 2,40 поисковых выстрела соперника в наш флот за 20; против «Ранил? Прости» 0,30 против 4,44. Клиент не заменяет её на `fleet-mc-hunger` при HUNGER_GAMES. Подробности — в [журнале](../experiments/bot2.md).
