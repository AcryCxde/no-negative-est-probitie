# Почему fleet-mc проигрывает HARD

Дата разбора: 2026-10-10. Experiment: `hard-v1-diagnosis`.

Главный обнаруженный недостаток — модель расстановки соперника. В восьми матчах HARD все 43 полностью раскрытых многопалубных корабля находились целиком на внешнем периметре, а все 20 раскрытых однопалубников — внутри. Текущий fleet-mc сэмплирует допустимые флоты без такого предпочтения. Это сильная гипотеза для следующего изменения, но ещё не результат боевой проверки новой стратегии.

## Источник и метод

- Источник чисел: `data/bot2/analytics.duckdb`, таблица `events`. JSONL остаются первичным журналом.
- HARD: два запуска `4da52904-e860-416a-a1d9-26add722f598` и `90e2d0ab-52d0-48f7-a4ec-d260e1cfb71b`: 2 победы / 6 поражений.
- Контроль MEDIUM: два запуска `1f3768ec-b85e-4d3a-9068-1a6db2e21d6d` и `dc1bc10d-ce61-4d81-9c73-97539b958545`: 10 побед / 0 поражений.
- Все эти матчи: обычные правила, без модификатора. Длина корабля и его клетки восстановлены из HIT/SUNK: при запрете касания связная группа попаданий после SUNK определяет весь корабль.
- Поиск — выстрел при отсутствии незакрытых HIT; добивание — при их наличии. Для соперника это классификация по наблюдаемому состоянию, а не доступ к его внутреннему алгоритму.
- Полные расстановки противника в поражениях неизвестны. Из 48 многопалубных кораблей HARD полностью раскрыты 43; из 32 однопалубников — 20. Нераскрытые корабли не включены в геометрическую статистику.
- Доли попаданий относятся к фактически выбранным клеткам и разным полям; это не оценка эффекта альтернативной стратегии на одинаковых расстановках. Поражения обрывают нашу последовательность выстрелов: их длина не равна числу выстрелов до уничтожения всего флота.

## 1. Поиск не соответствует расстановке HARD

| Наблюдение | MEDIUM | HARD |
|---|---:|---:|
| Раскрытые многопалубные корабли целиком на краю | 20 / 60 | **43 / 43** |
| Раскрытые однопалубники внутри поля | 20 / 40 | **20 / 20** |
| Наши попадания при поиске на краю | 45 / 175 (25,7%) | **45 / 95 (47,4%)** |
| Наши попадания при поиске внутри | 55 / 235 (23,4%) | **20 / 185 (10,8%)** |

Все попадания внутрь поля HARD были SUNK однопалубников; незакрытых HIT внутри не было. При этом 185 из 280 наших поисковых выстрелов направлены внутрь. Из 215 промахов поиска 165 пришлись на внутренние клетки.

В этих выбранных клетках средняя оценка MC внутри была около 24,2%, фактическая доля попаданий — 10,8%; на краю оценка около 26,9%, фактическая доля — 47,4%. Общая средняя оценка 25,1% против 23,2% попаданий скрывает эту разницу между зонами.

Причина в реализации: `FleetMC.choose()` строит оставшиеся корабли из всех допустимых позиций, выбирая по очереди случайную позицию каждого корабля. Модель не использует тип соперника или найденное распределение расстановок. Последовательная генерация также не даёт равномерную выборку флотов; это уже явно отмечено в коде. Увеличение числа сэмплов не исправляет неверную модель соперника.

## 2. Основные потери — в поиске, а не в добивании

| Фаза в восьми матчах HARD | Наши попадания / выстрелы | HARD: попадания / выстрелы |
|---|---:|---:|
| Поиск | 65 / 280 (23,2%) | 74 / 266 (27,8%) |
| Добивание | 74 / 101 (73,3%) | 79 / 125 (63,2%) |

Наши 242 промаха: **215 в поиске и 27 в добивании**. Добивание на этой выборке точнее, чем у HARD; оно не выглядит главным ограничением. Пять промахов добивания были направлены внутрь поля, хотя все раскрытые многопалубные корабли HARD лежали вдоль края: предпочтение продолжения по периметру тоже заслуживает отдельной проверки.

В трёх из шести поражений у HARD оставались только однопалубники: два, один и один. В четвёртом матче последнего запуска, после уничтожения всех крупных кораблей, мы сделали 14 выстрелов и нашли один из двух катеров; последний остался жив. Четыре из этих выстрелов ушли на внешний край и оказались промахами. После потопления предпоследнего катера было ещё 10 промахов подряд.

Это показывает необходимость смены предпочтений в конце игры: для наблюдаемого HARD после крупных кораблей нужно искать катера внутри. Само по себе увеличение MC с 1000 флотов не добавит сведений о катерах: при единственном катере и равномерной модели все допустимые клетки равновероятны, а максимум частоты в конечной выборке может быть просто шумом.

## 3. Почему MEDIUM проходили легко

MEDIUM сделал **131 из 518** выстрелов в клетки, пустоту которых уже можно было вывести из диагоналей HIT и ореолов SUNK. HARD не сделал таких выстрелов в восьми матчах. Эти выстрелы допустимы по протоколу, но тратят ход впустую.

MEDIUM дал нам запас времени за счёт этих ошибок. HARD лучше использует ограничения поля, поэтому прежнего качества поиска уже недостаточно. Результат 10/10 против MEDIUM не доказывал превосходство над HARD.

## 4. Инфраструктура и состояние не объясняют поражения

- Все восемь матчей закончились `FLEET_DESTROYED`; технических ошибок в них нет.
- Перепроигрывание 381 нашего выстрела не выявило повторов, стрельбы в выведенные пустые клетки, несовпадений DECISION/SHOT_RESOLVED или некорректного уменьшения счётчика флота при SUNK.
- Результаты выстрелов HARD согласованы с нашей известной расстановкой.
- На всех 280 поисковых ходах HARD MC успел набрать 1000 флотов; переходов на fallback не было.
- p95 выбора/отправки хода — 50,4 мс, максимум — 60,6 мс при лимите 1 с. Это время клиентского обработчика, а не полная сетевая задержка.

## 5. Расстановка — второй независимый кандидат

В каждом из восьми матчей первый выстрел HARD был `(3, 3)` (координаты с нуля). При промахах встречается повторяющееся начало `(3, 3) → (4, 4) → (5, 5) → (6, 6)`; при попадании и выведенных ореолах последовательность меняется. Наш генератор не учитывает этот дебют. В самом быстром поражении HARD уничтожил наш флот за 33 выстрела.

Можно отдельно проверить расстановку с избеганием частых первых клеток поиска HARD. Пока нельзя утверждать, что проигрыш за 33 выстрела вызван именно генератором: это один матч. Не следует одновременно менять атаку и защиту, иначе причина улучшения останется неизвестной.

## Следующий эксперимент

1. Сохранить `fleet-mc` как сравниваемую исходную стратегию. Добавить отдельную стратегию для TRAINING/HARD: предпочтение многопалубных кораблей на краю и катеров внутри; использовать это предпочтение и при добивании.
2. Сначала изменить только стрельбу. Быстро проверить допустимость решений, учёт HIT/SUNK и работу запасного пути при наблюдениях, противоречащих шаблону.
3. Сравнить с исходной стратегией в чередующейся серии HARD. Записывать победы, рейтинг, промахи поиска/добивания, доли попаданий по зонам, оставшийся флот и первого стрелка. Восемь текущих матчей показывают направление, но не дают точной оценки ожидаемого выигрыша.
4. Затем отдельно проверить адаптированную расстановку. Предпочтения HARD не переносить автоматически на неизвестных рейтинговых соперников; там нужен отдельный выбор модели или адаптация по наблюдениям.

## Повторить расчёт

Из `bot_2/battleship_hack`:

```bash
uv run python scripts/analyze_hard.py --output data/bot2/hard-analysis-summary.json
```

Скрипт читает DuckDB в режиме read-only, не обращается к серверу и не загружает токен. В JSON сохраняет сводку и восстановленные клетки потопленных кораблей HARD. Новые бои и изменения игровой стратегии при этом разборе не выполнялись.
