## Что улучшать

1. **Расстановка — главный кандидат.** Базовый список `RIM_HUNTERS` содержит только «Банька Парилка» и «История про Минск». Против остальных многопалубные корабли всегда идут на край. Изменившееся поведение соперников такой список не учитывает. В последней разобранной серии «Ранил? Прости» набрала 11 попаданий, «Хранители» в проигранных боях — 16 и 15. Уже подготовленная в рабочем дереве `fleet-mc-hunger-heat` меняет расстановку по карте команды; v2 наследует её без изменения.
2. **Добивание использует сырые количества положений.** При открытых попаданиях `FleetMC.choose()` сразу переходит к `Density.density_choice()`. Полные расстановки и остаток выстрелов там не оцениваются; это эвристический счёт положений, а не оценка вероятности попадания в согласованном целом флоте. Поиск базовой hunger при этом уже учитывает ценность длинного корабля и остаток бюджета.
3. **Щит имеет цену в выстрелах и рейтинге.** Базовая hunger применяет его при любом открытом раненом нашем корабле, даже без устойчивой оценки точности соперника. После DEFENDED клетка остаётся доступной, и соперник может выстрелить туда ещё раз. Порог точности из heat сохранён, дополнительно v2 пропускает щит при нашем открытом добивании. Полезность этого дополнительного запрета требует живого сравнения.

## Реализованная вариация

Отдельное имя **`fleet-mc-hunger-v2`**, класс `FleetMCHungerV2`. Базовая стратегия и автоматический выбор hunger сохранены.

- Расстановка и карта команды унаследованы от heat: обновление после партии, сглаживание к общей карте, случайная доля расстановок.
- При открытых попаданиях сначала выбираются корабли, покрывающие все кластеры попаданий, затем достраивается остальной флот. Исключены варианты полностью подбитого корабля без SUNK, сохранены запрет касания и все известные пустые клетки. Выборки взвешиваются с учётом вероятности последовательного выбора; это модель при нейтральной гипотезе расстановки соперника.
- Для оставшихся ≥2 выстрелов используется существующий расчёт ожидаемых попаданий на следующих двух выстрелах с ветвями MISS/HIT/SUNK. Если остался один — максимальная оценка попадания. Это короткий горизонт, не оптимизация всей партии на 20 шагов.
- Бюджет вычисления добивания 80 мс, из него 65% на выборку; максимум 256 принятых флотов. При <30 выборках или эффективном размере <30 остаётся прежнее допустимое добивание.
- SHIELD не прерывает наше добивание. Поиск без открытых попаданий оставлен прежним.

## Проверка

`uv run battleship-hack smoke` прошёл: сохранение выбранной v2 в протоколе, подключение heat, допустимая расстановка, выбор одного/двух выстрелов на маленьком поле с известными вероятностями, запрет щита во время добивания, fallback при недостатке эффективных выборок, локальный WebSocket/reconnect и импорт журнала. `compileall`, `run --help`, `git diff --check` также прошли.

`uv run python scripts/sim_hunger.py 160 20 hunger hunger-v2`, одинаковые доски и seed для пар:

| Доски | hunger | hunger-v2 | Разница ± стандартная ошибка |
|---|---:|---:|---:|
| 160 восстановленных полных флотов соперников | 7,49 | 7,41 | −0,08 ± 0,16 |
| 160 случайных допустимых флотов | 7,84 | 8,00 | +0,16 ± 0,18 |

Метрика — попадания за 20 выстрелов. Преимущество новой стрельбы **не подтверждено**; обе разницы в пределах шума. Восстановленные полные доски преимущественно из старых побед, поэтому не представляют все нынешние hunger-матчи. Симуляция не проверяет нашу расстановку, SHIELD и рейтинг. Seed задаёт случайность, но выборка ограничена временем, и её размер может зависеть от нагрузки компьютера. Для симуляции ограничено число процессов до четырёх.

Живые матчи новой v2 в рамках этого ревью не запускались. Следующий эксперимент — чередовать v2 с базовой hunger или heat на этом же боте, сравнивать попадания обеих сторон и исходы по соперникам.

Дополнительно `uv run python scripts/replay_hunger_placement.py HUNGER_GAMES 1`: 189 записей матчей с ≥10 выстрелами соперника, один seed на запись, карта только из предшествующих записей. Поисковые выстрелы соперника за первые 20 действий в наш флот: фактическая расстановка 2,90; базовая hunger **2,88**; heat, унаследованная v2, **2,13** (−26%); heat без случайной доли 2,02. p95 времени выбора расстановки 321 мс. Против «Ранил? Прости» hunger 5,35 → heat 0,53, «Хранителей» 3,23 → 2,72, «Нейро Мугивары» 4,67 → 2,33. Против «Баньки» 1,73 → 1,97 — ухудшение на этой выборке. Эта проверка охватывает более широкую выборку HUNGER_GAMES, включая уже записанные матчи heat; скрипт не требует завершённого матча. Добивание после нового попадания не моделируется, поэтому измерен первый контакт с флотом, а не число итоговых попаданий и не доля побед.

## Запуск

Из `bot_2/battleship_hack/`:

```bash
uv run battleship-hack run --mode RANKING --strategy fleet-mc-hunger-v2 --matches 10 --max-seconds 3600 --experiment hunger-v2-ranking-20
```

`--matches 10` — десять партий. Лимит 20 выстрелов назначает сервер через `MATCH_STARTED.rules.shotLimitPerPlayer`; в CLI он не задаётся. Метка эксперимента правила партии не меняет. `--max-seconds 3600` увеличивает общий лимит запуска по сравнению с 360 секундами основной конфигурации.
