# Спидран: выбор стратегии и проверка клиента — 2026-10-10

Текущий выбор для bot2 — `fleet-mc-speedrun-v2`. Основной выигрыш даёт модель
расстановки HARD; преимущество добивания v2 над v1 пока небольшое и статистически
неубедительное. После исправления повторных выстрелов последняя серия: **5/5 побед**,
**40,8 засчитанного выстрела** до уничтожения флота, включая один таймаут.
Глобальная оптимальность стратегии не доказана.

## Правила и подтверждённая модель

Живые `MATCH_STARTED`: SPEEDRUN, поле 10×10, флот 4×1 / 3×2 / 2×3 / 1×4,
корабли не касаются даже диагонально, лимит 100 выстрелов, срок действия 1 с,
партия до 210 с. Платформа расставляет общий флот как у HARD; `PLACE` не нужен.
Побеждает меньшее число выстрелов до потопления. Таймаут тоже расходует выстрел.
Правила: [guide.md](../../../docs/platform/guide.md),
[результаты повторного выстрела](../../../docs/platform/values.md).

Первые 10 полностью раскрытых живых полей подтвердили:

- Все шесть многопалубных кораблей целиком на периметре.
- Четыре катера внутри поля, по одному в каждой четверти.

Это наблюдаемый шаблон генератора, а не дополнительное формальное правило.
Стратегия возвращается к общей модели при противоречащем наблюдении.

## Почему стратегия для Голодных игр здесь проигрывает

В Голодных играх важно получить больше попаданий за короткий лимит и спрятать
свой флот от конкретного соперника. В Спидране свой флот не участвует, все 20 клеток
цели надо поразить, а лишний промах ухудшает результат. Heat-расстановка и
поправки к расстановкам команд не дают преимущества против общего генератора HARD.

Выбранная стратегия:

1. Ищет многопалубные по вероятностной карте периметра; при почти равных оценках
   использует чётность, которая пересекает каждый прямой корабль длиной ≥2.
2. Добивает по выборке целых флотов, согласованных с попаданиями и правилом
   касания, с оценкой двух следующих выстрелов.
3. После уничтожения многопалубных точно считает допустимые размещения катеров
   по четвертям, учитывая запрет касания через границу.
4. Не использует бонусы. DISTANCE/SONAR стоят выстрел, защитные бонусы здесь
   бесполезны; в фактических матчах набор бонусов пуст.
5. Держит только один отправленный выстрел без результата, чтобы задержки не
   порождали повторные выстрелы.

## Парное сравнение стрельбы

20 полностью раскрытых реальных полей HARD/SPEEDRUN × 3 seed, 60 прогонов каждой
стратегии. Каждая стратегия стреляет по тому же полю с тем же seed. Потопления
объявляются как в Спидране; таймауты и сетевые задержки здесь не моделируются.

| Стратегия | Среднее до полного потопления | Медиана | Разница с hunger-v2 |
|---|---:|---:|---:|
| fleet-mc-hunger-v2 | 62,47 | 64 | — |
| fleet-mc-speedrun | 45,20 | 45 | −17,27 |
| fleet-mc-speedrun-v2 | **44,20** | **44** | **−18,27 (−29,2%)** |

V2 лучше hunger-v2 в 57/60 прогонов. Стандартная ошибка средней разницы,
сгруппированная по полю: 1,75 выстрела. V2 против speedrun-v1: −1,00 ± 0,93
выстрела (стандартная ошибка), 34 выигрыша / 3 равенства / 23 проигрыша.
Это не подтверждает устойчивое превосходство v2 над v1.

Ни один прогон не отключил модель и не использовал fallback. Максимальное
время выбора v2 — 29,8 мс. Выборка содержит только полностью раскрытые поля и
смещена к полям, которые мы смогли закончить; неполные поля не достраивались.
Повторные seed не являются новыми независимыми полями. MC имеет бюджет по
времени, поэтому результаты зависят от оборудования.

Исходные данные: `data/bot2/speedrun-replay-20.json`.
Пилот: 10 полей × 3 seed, 62,87 / 45,10 / 42,67 выстрела;
`data/bot2/speedrun-replay.json`. Расширение ослабило первоначальную оценку
преимущества v2 над v1.

## Исправление задержанных ответов

В серии на 10 матчей было 6 таймаутов, 3 `SHOT_REJECTED` и 4 поздних
`COMMAND_REJECTED`. Решения занимали миллисекунды, но между отправкой и
ответом возникали задержки более секунды. Клиент отвечал на новый
`TURN_REQUESTED`, пока результат предыдущего выстрела ещё не пришёл.
Он часто повторял ту же клетку; повторный выстрел законно считается MISS.
В одном таком матче получилось 89 результатов выстрела.

В `Protocol` добавлен `pending_speedrun_shot`: до результата предыдущего
выстрела новые запросы логируются как `ACTION_DEFERRED`. Результат, отказ,
снимок восстановленной партии и новая партия/завершение сбрасывают ожидание.
Другие режимы используют прежний порядок действий. В последней живой серии
одна задержка снова произошла: защита сработала, следующий выстрел был сделан
после результата, матч выигран. Она предотвращает дублирование, но не устраняет
сетевые или серверные задержки и их собственную стоимость в выстрелах.

Smoke проверяет последовательность SHOOT → TIMEOUT → TURN_REQUESTED → поздний
SHOT_RESOLVED → TURN_REQUESTED и освобождение ожидания после отказа/завершения.
Полный smoke, compileall и `git diff --check` прошли.

Первые пять боёв сохранили JSONL, но импорт в общую analytics.duckdb был
отклонён из-за другого процесса с блокировкой БД. Для последующих серий
использована отдельная БД `data/bot2/speedrun-eval/analytics.duckdb` и внешняя
блокировка общего `data/bot2/run.lock`, чтобы не открыть второй процесс bot2.
Исходные журналы сохранены; результаты первого запуска читаются напрямую.

## Воспроизведение и запуск

Из `bot_2/battleship_hack/`:

```bash
uv run battleship-hack smoke
uv run python scripts/replay_speedrun.py --boards 20 --seeds 3 --workers 2
uv run battleship-hack run --mode RANKING --strategy fleet-mc-speedrun-v2 --matches 10 --max-seconds 600 --experiment speedrun-v2-ranking
```

Скрипт сохраняет идентификаторы использованных полей и seed в JSON. По мере
появления новых логов набор полей при повторном запуске изменится; сохранённый
JSON фиксирует набор именно проведённого сравнения. Для отката добивания:
`--strategy fleet-mc-speedrun`; защита от повторной отправки остаётся.

Следующий содержательный эксперимент — совместно учитывать четверти катеров
уже во время поиска многопалубных: текущий sampler применяет это ограничение
точно только в конце. Проверять на новых полях, отложенных от выбора параметров.
